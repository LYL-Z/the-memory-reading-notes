126,936 = 825,901 − 698,965。表面上是个"倒挤"数，**但它后来被验证为真**：

另 22 条记录的 `read_range` 形如 `all 198 lines`，无字数。这 22 章用官方脚本实算之和＝**126,936**，分毫不差。所以这个残差数是对的——但**它是先有结果后有验证**，报告里不能说成"实测"。

22 章构成：V7-001..009/013..015/020（13 章）＋ V1-018（1 章）＋ V2-001..008（8 章）。

### 1.4 766,577 / 92.8% —— 这才是真正的错误，且我能定位到具体漏了哪几章

反推分子：

```
766,577 = 698,965 + 67,612
67,612  = V1-018(7,080) + V2-001..008(60,532)
```

即：**113 个有字数的章 ＋ 9 个 V1/V2 的「all N lines」章，唯独漏掉了 V7 的 13 个「all N lines」章。**

```
825,901 − 766,577 = 59,324 = V7-001..009,013..015,020 实算之和
```

**根因**：V7 不在工作树里，须 `git show pr/84:` 取文；算分子那一步对 V1-018 和 V2-001..008 补了实算，对 V7 的同形态记录没补，于是 13 章整段丢失。分母仍是全量 825,901，比值就被压低到 92.82%。
