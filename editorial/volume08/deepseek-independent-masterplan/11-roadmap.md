# 长期计划｜分批推进、验收口径、以及怎么在写的过程中改设计

## 一、先说我对现有设计的三类判断

### 值得原样保留

| 内容 | 来自 | 为什么保留 |
|---|---|---|
| 八架构全部采用、不强制合流 | GPT-6.2 V2 | 它把"选择"这个动作从作者身上拿走了，这是对的。作者不该在动笔前做架构选择题 |
| 章可含任意小节、章数篇幅无上限 | GPT-6.2 V2 | 直接解决了"体量越来越少"的老问题 |
| 硬科幻开篇 | 作者裁定 | 这是全书唯一一个"必须"的位置，因为它决定了这本书是什么类型 |
| 皇家三类并行 | 作者裁定 | 三类各自能讲不同的故事，且互相不干扰 |
| 现行后台制度的事实分级与红线 | 2026-11-20 | 这套东西是对的，只是需要加正面要求（见 [10-institution-review.md](10-institution-review.md)） |
| "不要每章都回响旧物件" | V2 及各轮共识 | 这是七部最明显的病灶，已经诊断准确 |

### 需要重构

| 内容 | 问题 | 我的处理 |
|---|---|---|
| RCD 关系时域 | 没有成本函数、没有不对称、不产生主题 | 换成钟隙理论，代价律与真度—通度反比（[02-physics.md](02-physics.md)） |
| 四十个故事模块（O01–O40） | 每一个都是"入口 + 兑现"，缺少"之后" | 保留作为素材库，但**每用一个必须补两场**：一次失败、一场之后 |
| "章"作为交付单位 | 无法支撑无限扩展 | 改为册制（[04-architecture.md](04-architecture.md)） |
| 轮流上场制 | 读者在意"然后呢"，不是"同时呢" | 放弃 |
| 十五个原创人物 | 语域过于统一 | 换成十六个，混四种语域（[08-characters.md](08-characters.md)） |

### 建议舍弃

| 内容 | 理由 |
|---|---|
| "每一条世界线都必须活到老" | 强迫寿命平均，会让短的那条变成残次品。**有些人生就该早早结束** |
| "全卷只交汇一次"（PR #93） | 这是为了防止"年夜饭"被滥用，但代价太大。改为"交汇不得超过三次，且每次必须改变结构" |
| "现实母线必须回到 2027 年春节" | 未来尚未发生，不能把现实写成已发生 |
| 用"四个梦"当全卷骨架 | 四个梦是**情感原点**，不是结构。用它们当骨架，第八部会变成对前七部的补偿 |
| 三开篇、材料卡、伏笔表作为每章强制 | 已经是可选，建议在宪章里彻底降为"工具"，不进流程 |

## 二、分批推进（批次不等于时间表）

### 第 0 批｜准备（不动笔）

- 按册建立世界账模板（[04-architecture.md](04-architecture.md) 第八节的字段）；
- 把钟隙理论的五条公设写成**一页纸**，供每册开工时贴在前面；
- 建立"代价账"：谁在承担、承担了多少、什么时候显形；
- 补读：铰册 I 涉及的人物页与相邻章（不要求通读 135 章）。

**验收**：一页纸公设 + 一册世界账 + 一份代价账。三样东西加起来不超过两千字。**如果准备材料超过两千字，说明又在做设计而不是准备写作。**

### 第 1 批｜铰册 I《校准》22 章

按 [03-opening.md](03-opening.md) 的节拍表写。第一次"渡"必须发生在第 20 章之后，**不许提前**。

**验收**：
- 有 1 次"当众、可验证、有后果"的兑现（第 19 章）；
- 有 1 场"之后"（第 22 章之后应有一节写他回实验室的日常）；
- 读者读完能回答："这个人是谁，他要什么，他怕什么"。

### 第 2 批｜游册《观星台》16 章

帝国线第一次完整落地。**必须先解决一个技术问题**：古代世界的语言、官制、度量衡、农时，至少要有内部一致的写法，不能凭印象。

**验收**：能通过一个测试——**把这一册给一个完全没读过前七部的人看，他要能读懂，并且想知道后面。** 这就是册制的核心指标。

### 第 3 批｜游册《两把钥匙》12 章

独立成年关系线。这一册的任务不是"写爱情"，是**证明这本书能写活人的日常**。

**验收**：全册至少有三场戏，删掉不影响情节，只影响你对这两个人的感情。

### 第 4 批｜铰册 II《账单》18 章

代价律第一次显形，团队第一次分裂，M4（借隙）第一次被提出。

**验收**：读者必须在这一册里第一次感到"这个能力是可怕的"，而不是"这个能力很酷"。

### 第 5 批以后｜交替推进

按 [04-architecture.md](04-architecture.md) 第六节的册序。每写完两个游册，插一个铰册；每写完一个铰册，插一个镜册。

**没有终点批次。** 写到第 N 册时如果还有新东西，就继续；如果没有，就按 E1 或 E6 收。**册制的作用就是让"停"永远是一个体面的动作。**

## 三、验收口径：不用字数

这是我认为必须写进制度的一条。

| 不用的指标 | 原因 |
|---|---|
| 总字数 | 已经证明会制造"为凑字重复"（七部的 V1.2 就是教训） |
| 章均字数 | 同上 |
| CI 分数、检测分 | 与文学品质无关 |
| 报告数量 | 报告不能替代作品 |

| 用的指标 | 具体怎么判 |
|---|---|
| **可独立阅读** | 抽一册给没读过的人，他能不能读懂并想知道后面 |
| **"之后"配额** | 每册是否至少有一场兑现之后的日常 |
| **代价是否显形** | 每册结束时，代价账上是否新增了条目，并且读者能看见 |
| **人物是否有自己的事** | 抽三个配角，问：他在主角不在场的时候在干什么？答不出来就是纸片 |
| **删句测试** | 随机抽三段，删掉最后一句，有没有损失 |

**关于最后一条我要说清楚**：这是编辑工具，不是评分。它只用来找问题，不用来证明好。

## 四、怎么在写的过程中改设计

设计不是一次定完的。但"边写边改"很容易变成"边写边推翻"，最后一册也写不完。所以我给三条触发器——**只有触发时才改，其余时候不改**。

### 触发器 1｜文本触发（最常用）

写完一册，如果出现下面任一情况，改设计：

- 某一册写到一半，发现主角的最优选择是"不用能力"——说明代价律定得太重，或情节逼得不对；
- 某个配角在写作中自己长出了比主角更强的动机——**不要压回去，改主线**；
- 某一册写完，你自己不想再读第二遍——不是写得差，是这一册没有存在理由。

### 触发器 2｜读者触发

给一个真实的、非亲友的读者读一册，只问三个问题：
1. 你读到哪一段想放下？
2. 你最想知道后面什么？
3. 你觉得哪个人物是假的？

**注意**：目前"真人陌生读者完整独立冷读：0"。这个数字不改变，任何"读者反馈"的说法都不成立。

### 触发器 3｜作者触发

你自己改主意了。这是最高优先级的触发器，**不需要理由**。但它有一个程序要求：改主意必须写成一句话记下来（"我把 X 换成 Y，因为……"），附在原设计后面，**不删旧的**。这样三个月后你能看见自己改过什么。

## 五、风险登记

| 风险 | 概率 | 后果 | 缓解 |
|---|---|---|---|
| 册制变成"永远写不完" | 高 | 读者流失，作者疲惫 | 每册独立收口；允许在任何一册之后停 |
| 代价律让主角变得被动 | 中 | 爽感消失 | 代价是**可预期的**，不是随机的；他知道要付什么，仍然选择付 |
| 两个世界线互相拖累 | 中 | 读者跳读 | 册制：一册之内不切 |
| 科学段落写成了科普 | 高 | 节奏断 | 公式只在改变选择时入文；推导进"实验记录"小节 |
| 成年线写成了"证明自己成年" | 中 | 假 | 参照 [07-intimacy.md](07-intimacy.md)：写决定、写之后、写不 |
| 帝国线写成"主角很伟大" | 高 | 廉价 | 按 [05-empire.md](05-empire.md)：写预算、写执行、写一个工人的手术费 |
| 模型合稿磨平声音 | 高 | AI 味 | 保连续段落不保句子；每次合稿记录"保留了哪一段的哪一点" |

## 六、协作分工（不改现行边界）

我不在这里重新分配模型职责——现行的 [05-model-workflow.md](../2026-11-24-open-epic/integration-v2/05-model-workflow.md) 已经写得比较合理。我只补三条：

1. **一律按实际文本判断，不按报告判断。** 一份两万字的方案不如一章两千字的成稿。
2. **不让任何一个模型承担"只有它能做"的内容。** 凡是指定某家"专门写某类段落"的分工，都要重新检查是否构成规避。
3. **本轮三方独立设计之后，整合者的第一件事应该是"删"，不是"合"。** 三份方案合在一起会得到一份谁都不像的东西。正确顺序是：先各自指认对方的哪一处比自己强，再决定删掉自己哪一半。
